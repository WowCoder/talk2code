三个角色，一套流程

不是一次生成了事，而是分工协作

LangGraph 编排三个智能体，职责分离、相互校验，把工程质量当成一等公民。

TL
TeamLeader

技术负责人

把一句自然语言需求拆成结构化 Plan 与验收条件（AC），并判定复杂度等级，决定走快速通道还是完整流程。

CD
Coder

开发工程师

批量创建文件，迭代轮数由文件数自适应决定；写入即返回内容预览，避免重复回读浪费上下文。

QA
QA Engineer

质量工程师

用 Playwright 在真实 headless Chromium 里逐条执行验收条件，全部通过走快速通道，否则按缺陷类别路由回炉。

🟢 simple 快速通道 单个页面、极简交互：轻量分析 → 5 轮快速编码 → 预览验证 → 完成。
🔵 standard 完整流程 多文件交互式应用：完整 Plan + AC → 用户确认 → 批量编码 → AC 逐条验收 → 交付门禁放行。
为什么不一样

交付前，先过工程质量这一关

多数工具止步于吐出代码片段；Talk2Code 要求生成结果能打开、能点、能用，才允许放行。

能力做法
◆多智能体分工LangGraph 编排技术负责人 / 开发工程师 / 质量工程师，职责分离而非一次生成了事
◆真实验收质量工程师用 Playwright 在 headless Chromium 里逐条执行 AC，以运行结果为准
◆交付门禁关键缺陷清零才放行，未达标则转人工确认并附差异报告
◆跨文件契约计划期声明 exports → 编码期契约注入 → 验收期闭合校验，保证模块间真正接通
◆写入即拦截PRE_WRITE Hook 零 LLM 成本拦掉沙箱环境必失败的写法，把问题挡在生成之前
◆缺陷自动回炉验收不通过时按缺陷类别路由回开发工程师重构，架构类附根因卡片，修完再验
◆回归纪律固化 21 个回归任务，改核心逻辑前后跑基线对照，经验沉淀进跨会话记忆

快速开始

三步跑起来

本地或服务器均可，配置好一个 LLM API Key 就能用。

  1. 安装依赖创建虚拟环境并安装后端依赖包。
  2. 配置模型复制配置模板，填入你的 LLM API Key（兼容 OpenAI / Anthropic 协议）。
  3. 一键启动执行启动脚本，打开浏览器访问即可使用。
bash 
# 1. 安装依赖
python -m venv venv && source venv/bin/activate
pip install -r backend/requirements.txt

# 2. 配置模型（填入 LLM_API_KEY）
cp backend/.env.example backend/.env

# 3. 一键启动 → http://localhost:5001
./start.sh

✔ 服务已就绪，输入一句话需求试试
