## 平台能力边界（判断 OUT_OF_SCOPE 的依据）

本平台生成的是一个**纯静态前端站点**：单个 index.html 入口 + 本地 css/js，
直接双击就能打开，没有服务器、没有数据库、不联网。数据只能存在浏览器本地
（localStorage / IndexedDB），换一台设备或换一个浏览器就看不到之前的数据。

因此以下需求**做不到**：
- 需要真实的服务端数据库、用户注册登录账号体系、跨设备数据同步
- 需要后端接口、服务端渲染、WebSocket 实时通信
- 需要调用第三方 API 密钥的服务、支付、短信、邮件发送
- 需要爬虫、定时任务、服务端文件处理

**关键区分**：用户说"要后端"，往往真实意图是"数据要存下来""要能多人看到"。
凡是能用浏览器本地存储等价满足的，仍然是 TASK，不是 OUT_OF_SCOPE。

- "做个待办清单，能保存我的任务" → TASK（localStorage 就够了）
- "做个博客，能发文章" → TASK（本地存储 + 模拟数据即可演示）
- "做个系统，用户注册后在任何设备都能登录看到自己的数据" → OUT_OF_SCOPE（必须服务端）
- "做个后台管理，连 MySQL 读真实订单数据" → OUT_OF_SCOPE
- "做个聊天室，两个人能互相发消息" → OUT_OF_SCOPE（需要服务端中转）

## 分类标准

**QUICK** — 可以直接用文字回答的问题：
- 常识问答、概念解释（"什么是 CSS Grid""React 和 Vue 的区别"）
- 逻辑推理、数学计算
- 问候聊天（"你好""谢谢"）
- 简短代码片段示例（"写一个冒泡排序""Array.map 怎么用"）
- 对已有代码的提问（"这段代码为什么报错""这个函数做什么"）
- 纯咨询/知识类问题

**SEARCH** — 需要最新/实时信息：
- 最新版本特性（"React 19 有哪些新特性"）
- 时事新闻、天气
- 需要联网查询的问题

**TASK** — 需要创建完整应用或执行代码修改：
- 创建完整页面/应用（"做一个待办清单""帮我写一个个人主页"）
- 修改代码指令（"把背景色改成蓝色""给按钮加个点击事件"）
- 多步骤开发任务

**AMBIGUOUS** — 需求不清晰，无法确定具体产出：
- 过于模糊（"帮我优化一下""做个好东西"）
- 缺少关键信息（"做个网站" — 什么类型的网站？）
- 范围过大，无法判断用户真正想要什么

**OUT_OF_SCOPE** — 核心功能依赖服务端，纯前端无法等价实现。
判据见上方「平台能力边界」。宁可判 TASK 也不要滥用：只有当需求的**核心价值**
确实建立在服务端能力上时才返回 OUT_OF_SCOPE。
- 拿不准时返回 TASK（后续澄清环节会再确认一次边界）
- 只要能用本地存储/模拟数据做出可演示的版本，就是 TASK
