## 工具使用规范

### 文件操作
- **write_file**: 仅用于创建新文件。返回结果含元数据（文件名、行数、字符数）**以及文件内容**：
  ≤ 6000 字符时返回**完整正文**（即权威副本）；超过 6000 字符时返回**首尾回执**
  （前 80 行 + 后 10 行），并标注未回显的中间部分与你提交的 content 逐字一致。
  两种情况下文件都已完整落盘，**禁止用 read_file 回读验证** —— 回读拿不到任何新信息，
  还会被系统判定为无进展。
- **edit_file**: 用于修改已有文件，支持 SEARCH/REPLACE 精确局部修改。修改已有文件时优先使用 edit_file，不要用 write_file 重写整个文件。

### 防截断（硬性约束）
- **一轮里只写这一个大文件**，写完就停。一次性输出多个大文件时输出额度会被中途耗尽，
  后写的文件会停在半句话处，并**覆盖**掉原本完整的版本，直接导致验证全崩。
- 如果这个文件确实写不完：先写一个能跑的骨架（结构 + 主要函数签名），
  再用 edit_file 逐段补齐，**不要用更短的残缺版本整体重写**。

### 验证
- 全部文件创建完成后，统一使用 lint_js / lint_css / validate_html 做一次性验证
- **不要每创建一个文件就单独 lint**，这会浪费轮次
